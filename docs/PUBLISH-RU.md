# Публикация и обновление мода (GitHub + Thunderstore)

Полная инструкция: как выложить мод в первый раз и как выпускать обновления.
Ничего программировать не нужно — только кнопки.

---

## Часть 0. Что где лежит

| Что | Где |
|---|---|
| Исходный код мода | эта папка (корень репозитория) |
| Скрипт сборки пакета | `tools\pack.cmd` (двойной клик) |
| Готовый пакет для Thunderstore | `dist\NpcSpawner-<версия>.zip` |
| Версия мода | в трёх местах: `manifest.json`, `NpcSpawner.csproj`, `Plugin.cs` |
| История изменений | `CHANGELOG.md` |

**Перед публикацией поменяй под себя:**
1. `LICENSE` — строку `Copyright (c) 2026 NpcSpawner contributors` → своё имя/ник.
2. `manifest.json` — поле `website_url` → ссылка на репозиторий (после шага 1 части 1).
3. `README.md` — при желании добавь свой ник в раздел Credits.

# Часть 1. Первая публикация

## 1.1. Выложить на GitHub

> `git` на компьютере не установлен, поэтому проще всего через **GitHub Desktop** —
> он и git поставит, и всё сделает кнопками.

1. Зарегистрируйся на https://github.com
2. Скачай и установи **GitHub Desktop**: https://desktop.github.com — и войди в него.
3. **File → Add local repository…** → выбери **эту папку** → **Add repository**.
   Он предупредит, что это не git-репозиторий — нажми **create a repository**.
4. Внизу справа поле **Summary** — напиши `First release` → **Commit to main**.
5. Сверху **Publish repository**. Сними галочку «Keep this code private», если хочешь публичный.
6. Скопируй адрес репозитория (**Code → HTTPS**) и впиши его в `manifest.json` в поле
   `website_url` — потом снова Commit + Push.

## 1.2. Выложить на Thunderstore

1. Аккаунт: https://thunderstore.io (вход через **Discord, GitHub или Overwolf** — по email нельзя).
2. Придумай **Team name** — имя автора, под которым выходят моды (потом не изменить).
3. Собери пакет: двойной клик по **`tools\pack.cmd`** → появится `dist\NpcSpawner-<версия>.zip`.
4. Открой **https://thunderstore.io/c/v-rising/create/**
5. **Submit Package** → выбери свой zip.
6. **Team** — своя команда, **Communities** — **V Rising**, **Categories** — подходящие теги
   (например *Server*, *Mods*).
7. **Submit**.

# Часть 2. Как ОБНОВИТЬ мод

> Thunderstore **нельзя редактировать**: любые правки (код, README, манифест) выпускаются
> **новой версией**. Поэтому обновление = поднять версию → собрать новый zip → залить заново.

## Шаг 1. Поднять версию в трёх местах

Версия должна совпадать везде (формат `Major.Minor.Patch`, например `1.7.2`):

| Файл | Что менять |
|---|---|
| `manifest.json` | `"version_number": "1.7.1"` |
| `NpcSpawner.csproj` | `<Version>1.7.1</Version>` |
| `Plugin.cs` | `PluginVersion = "1.7.1"` |

Правило нумерации: `Major.Minor.Patch`. Это **не** десятичная дробь: `1.7.10` новее `1.7.9`.

## Шаг 2. Дописать изменения в `CHANGELOG.md`

Сверху файла добавь новый раздел — что изменилось. Это видят люди на странице мода.

## Шаг 3. Собрать новый пакет

Двойной клик по **`tools\pack.cmd`**.
Скрипт сам соберёт мод и положит `dist\NpcSpawner-<версия>.zip`.
Старые архивы в `dist` можно удалять — они больше не нужны.

## Шаг 4. Обновить GitHub

1. Открой **GitHub Desktop** (папка репозитория уже подключена: это та же папка).
2. Слева увидишь список изменённых файлов.
3. Внизу в поле **Summary** напиши, что изменилось, например `v1.7.2: fix spawn in castles`.
4. Нажми **Commit to main**.
5. Нажми **Push origin** (сверху).

Готово — на GitHub лежит свежая версия.

## Шаг 5. Обновить Thunderstore

1. Открой **https://thunderstore.io/c/v-rising/create/**
2. **Submit Package** → выбери **новый** zip из `dist` (с новой версией в имени).
3. **Team** → своя команда, **Communities** → **V Rising**, категории → те же, что были.
4. **Submit**.

Новая версия появится на странице мода, а мод-менеджеры (r2modman, Thunderstore Mod Manager)
предложат обновиться.

# Часть 3. Если что-то отклонили

- **Иконка** — ровно `256×256`, формат PNG, имя строго `icon.png`.
- **Файлы в корне архива** — `manifest.json`, `icon.png`, `README.md`, `CHANGELOG.md`,
  а сам мод внутри `plugins\`. Если заархивировать папку целиком, файлы окажутся во вложенной
  папке и пакет отклонят. `tools\pack.cmd` делает правильно.
- **Имя пакета** — только латиница, цифры и `_` (`NpcSpawner` — ок).
- **Описание** в манифесте — не больше 250 символов.
- **Версия** — выше предыдущей.
- README должен быть в UTF-8 (файлы в репозитории уже такие).

# Часть 4. Локальная сборка (для разработки)

```
dotnet build -c Release
```

- Нужен **.NET SDK 6.0** или новее.
- Если рядом есть папка `libs\` с `BepInEx.Core.dll` — используются локальные сборки
  (удобно, когда фид NuGet недоступен). В GitHub папка `libs` не попадает: она в `.gitignore`.
- Если папки `libs` нет — проект тянет зависимости из NuGet (так собирает GitHub Actions).
